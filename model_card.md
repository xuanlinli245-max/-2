# Model Card — скрининг риска сердечно-сосудистых заболеваний

> **Кратко:** модель оценивает вероятность сердечно-сосудистого заболевания по 11 клиническим
> признакам и помогает врачу приоритизировать пациентов. Это не диагноз и не замена врачу.

## 1. Детали модели

- **Название:** `heart-disease-voting-ensemble`
- **Версия:** `1.1.0`
- **Тип:** бинарная классификация; soft-voting ensemble
  (Logistic Regression + Random Forest + HistGradientBoosting)
- **Разработчик:** Xuanlin Li, учебный ML-проект
- **Год:** 2026
- **Библиотека:** scikit-learn
- **Артефакт:** полный `Pipeline` (`model.joblib`), включая preprocessing и классификатор
- **Лицензия:** MIT (код); данные — см. страницу источника

### Архитектура

```text
запись пациента
  -> проверка схемы и диапазонов
  -> ZeroToNaN (Cholesterol=0, RestingBP=0 -> пропуск)
  -> числовые: median imputation + StandardScaler
  -> категориальные: most frequent + OneHotEncoder
  -> soft voting: LogReg (0.3) + RandomForest (0.4) + HistGradientBoosting (0.3)
  -> P(HeartDisease=1)
  -> порог 0.107 -> группа риска -> осмотр врача
```

## 2. Назначение и цель

**Цель модели.** Поддержка скрининга: по 11 рутинным клиническим признакам оценить вероятность
сердечно-сосудистого заболевания и помочь врачу понять, кого нужно посмотреть раньше.

**Решаемая задача.** Бинарная классификация: `HeartDisease = 1` (есть заболевание) или `0` (нет).
Модель не ставит диагноз, а выдаёт вероятность и группу риска для приоритизации.

**Основное использование.** На приёме или при первичном сборе данных: модель помогает
распределить пациентов по срочности врачебного осмотра.

**Пользователи.** Врач или медсестра на приёме; ML-инженер для мониторинга; исследователь для
ретроспективного анализа.

**Что модель не делает:**
- не ставит диагноз;
- не назначает лечение;
- не используется для экстренной триаж-системы;
- не применяется к пациентам до 18 лет;
- не применяется к популяциям, которых не было в обучающих данных;
- не показывается пациенту без врача.

Модель — **второе мнение**, а не замена врачу.

## 3. Входные и выходные данные

### Входные признаки (11)

| Признак | Тип | Значения / диапазон |
|---|---|---|
| Age | числовой | 18–100 лет |
| Sex | категориальный | M / F |
| ChestPainType | категориальный | ATA / NAP / ASY / TA |
| RestingBP | числовой | 50–250 мм рт. ст.; 0 = пропуск |
| Cholesterol | числовой | 0–700 мг/дл; 0 = пропуск |
| FastingBS | бинарный | 0 / 1 |
| RestingECG | категориальный | Normal / ST / LVH |
| MaxHR | числовой | 60–220 уд/мин |
| ExerciseAngina | категориальный | N / Y |
| Oldpeak | числовой | −3…+6; отрицательные значения допустимы |
| ST_Slope | категориальный | Up / Flat / Down |

### Выход

- `P(HeartDisease=1)` — вероятность от 0 до 1;
- `prediction` — 0/1 после выбранного порога;
- `risk_band` — low / medium / high;
- `threshold` и `model_version` — для аудита и воспроизводимости.

Вероятность **не откалибрована**; её нельзя показывать пациенту как клинический процент риска.

## 4. Факторы

- **Возраст и пол:** входят в модель; качество по подгруппам отдельно не гарантируется.
- **Популяция:** данные одного ретроспективного источника; другой регион может дать сдвиг.
- **Качество ввода:** ошибки в давлении, холестерине или ЭКГ влияют на результат.
- **Оборудование:** модель не использует сырые сигналы ЭКГ, только категорию `RestingECG`.

## 5. Метрики

### Кросс-валидация (5-fold, train)

| Метрика | Среднее ± std |
|---|---:|
| ROC-AUC | 0.931 ± 0.025 |
| Recall | 0.879 ± 0.034 |
| F1 | 0.872 ± 0.020 |

### Отложенный тест (184 пациента)

| Метрика | @ порог 0.50 | @ скрининговый порог 0.107 |
|---|---:|---:|
| ROC-AUC | 0.930 | 0.930 |
| PR-AUC | 0.937 | 0.937 |
| Recall | 0.863 | **0.971** |
| Precision | 0.907 | 0.739 |
| F1 | 0.884 | 0.839 |
| Accuracy | 0.875 | 0.793 |

Матрица ошибок @ 0.107: `TN=47, FP=35, FN=3, TP=99`.

95% bootstrap CI @ 0.107: ROC-AUC `[0.891, 0.963]`, recall `[0.933, 1.000]`,
precision `[0.659, 0.805]`, F1 `[0.786, 0.884]`.

### Выбор порога

Порог — **продуктовое решение**, а не свойство модели. Для скрининга максимизируем recall
при precision ≥ 0.70: порог 0.107 ловит 99 из 102 положительных, но даёт 35 ложных срабатываний.
Сбалансированный вариант 0.50 даёт 14 FN и 9 FP.

## 6. Данные обучения

- 918 ретроспективных записей, 11 признаков, цель `HeartDisease` (0/1).
- Train/test: 734 / 184, стратифицированно, `random_state=42`.
- Preprocessing обучается только на train, внутри Pipeline.
- Fingerprint данных хранится в `models/model_metadata.json`.

## 7. Данные оценки

- Отложенные 20% теста, не использовались для обучения и выбора порога.
- Порог выбран на out-of-fold предсказаниях train.
- Внешней валидации нет — это ограничение.

## 8. Этические соображения

- Не медицинское изделие; нет CE/FDA.
- Риск automation bias: врач остаётся лицом, принимающим решение.
- Нет аудита fairness по полу и возрасту; это блокер перед клиническим пилотом.
- Нет данных о курении, лекарствах, семейном анамнезе и социальных факторах.
- Персональные данные должны быть минимизированы, зашифрованы и обработаны по DPIA.
- High-risk результат формулируется как «требует врачебного review», а не как диагноз.

## 9. Ограничения

- 918 записей из одного ретроспективного источника; нет внешней и временной валидации.
- Вероятности не откалиброваны.
- Нет гарантии по подгруппам.
- Низкий порог 0.107 чувствителен к сдвигу распределения.
- Ретроспективный ROC-AUC не гарантирует проспективную клиническую пользу.

## 10. Поддержка и мониторинг

- **Триггеры:** квартал, PSI ≥ 0.2, recall < 0.90, новый источник, инцидент качества.
- **Release gates:** CV ROC-AUC ≥ 0.90; test recall ≥ 0.90; precision ≥ 0.70;
  fairness gap ≤ 0.05; schema и leakage tests проходят.
- **Rollback:** хранить предыдущий артефакт и metadata; переключить путь и перезапустить API.
- **Логирование:** версия модели, порог, hash входа, предсказание и решение врача.
